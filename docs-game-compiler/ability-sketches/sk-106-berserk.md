# SK-106: Berserk

## Designer Intent

I launch a wave of madness. Enemies hit go berserk for 2.5 seconds — they uncontrollably auto-attack their OWN ALLIES. They can't choose targets, they just lash out at the nearest teammate. If no allies are nearby, they auto-attack nothing (stand still, berserked). After the berserk ends, they regain control.

## Primitive Composition

P-28 (Hostility Inversion) → P-03 (Trajectory Steering) → P-26 (Capability Bitmask)

*See `ability-primitives/` for canonical definitions.*

## Inputs

- Caster entity
- AoE or skillshot delivery (projectile wave)

## Observable Behavior

1. Wave hits enemies — berserk applied for 2.5 seconds
2. Berserked enemies auto-attack the nearest ALLY (their own teammate)
3. Berserked enemies deal their normal auto-attack damage to their own ally
4. Berserked enemies cannot move voluntarily, cast abilities, or choose targets
5. If no ally is within auto-attack range: berserked enemy stands still (no target)
6. The forced attacks use the berserked entity's own offensive stats
7. The attacked ally takes real damage (this is actual friendly fire)
8. Duration reduced by Tenacity
9. Subject to Diminishing Returns (SK-28) — hard CC category
10. Cleansable by SK-15 Purify
11. Visual: red rage effect, berserked enemies visibly hitting their own allies

## Engine Primitives Required

Berserk is already one of the canonical `apply_cc` behavior profiles.

The recommended lowering is:

1. apply one hostile CC with:
   - `cc_type = berserk`
   - `category = target_override`
   - `duration_ticks = 150`
   - `duration_scaling = status_resistance`
   - an authored `dr_category` if the game wants berserk to share DR with other target-override CC
2. let the generated negative status use the canonical berserk profile:
   - suppress voluntary movement
   - suppress voluntary ability casts
   - rewrite engine-owned auto-attack target selection to the nearest ally
   - authorize ally damage for that forced auto-attack only

This keeps the mechanic entirely inside the canonical CC surface:

- berserk is not a bespoke "friendly fire mode" status
- nearest-ally targeting is generated by the `cc_type = berserk` behavior profile
- the ally damage is real damage, so ordinary Phase 1 / Phase 2 combat, crits, block, shields,
  on-hit effects, and defensive procs still resolve normally once the forced attack is admitted
- Tenacity / status resistance, DR, cleanse, and CC immunity all work through the same standard CC
  metadata used by other canonical crowd control

## Cross-Boundary Concerns

Berserk follows the canonical target-owner target-override contract.

1. The target's current owner admits the CC and installs the generated berserk status there.
2. While the status is active, that same owner performs nearest-ally auto-attack target selection
   each tick using local or Ghost ally data exactly the way taunt/fear/charm use source-relative
   local-or-Ghost identity.
3. If the selected ally is remote, the forced auto-attack still follows the ordinary cross-boundary
   combat relay path. The outgoing combat payload carries the canonical berserk-friendly-fire
   authorization generated by the CC profile.
4. The ally owner accepts that one same-team attack because the forced auto-attack was admitted
   under the berserk profile; ordinary same-team damage outside this path remains illegal.
5. If the berserked entity or its ally hands off mid-status, the status transfers as ordinary
   SoftState and the new owner continues the same nearest-ally retargeting behavior.

## Compiler Requirements

Designer specifies:

- delivery shape (wave / AoE / projectile)
- duration
- whether berserk is cleansable
- whether berserk participates in an authored DR bucket

Compiler emits:

- one hostile `apply_cc` with `cc_type = berserk`
- the generated negative status carrying canonical berserk behavior metadata
- the engine-owned friendly-fire authorization bit for forced berserk auto-attacks

Compiler validates:

1. `cc_type = berserk` pairs only with `category = target_override`
2. the mechanic is expressed through canonical `apply_cc`, not a bespoke auto-attack rewrite script
3. the ability does not invent a second hostility-inversion path outside the canonical berserk
   profile

## Resolved Interaction Notes

- Berserked auto-attacks crit normally, because the forced attack still uses the berserked entity's
  ordinary offensive pipeline.
- On-hit effects, lifesteal/drain, blocks, thorns, and other ordinary combat-side reactions still
  fire normally because the ally damage is real combat, not scripted fake damage.
- Berserk can kill allies. The profile authorizes same-team auto-attack damage; it does not apply a
  friendly-fire safety clamp.
- If no ally is currently in auto-attack range, the berserked entity stands still and performs no
  forced attack until a valid ally enters range.
- Unstoppable and other canonical `target_override` immunity effects block berserk admission the
  same way they block taunt.
- For ally-side defensive checks, the hit is still allied-source damage, not "enemy damage." The
  berserk profile only authorizes the damage; it does not rewrite team identity for downstream proc
  classification.
- If another target-override CC such as taunt overlaps, the runtime uses the ordinary canonical CC
  overlap/order rules; this reference does not grant berserk bespoke precedence over other admitted
  control effects.
