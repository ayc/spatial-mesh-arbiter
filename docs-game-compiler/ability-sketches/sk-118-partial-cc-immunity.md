# SK-118: Partial CC Immunity

## Designer Intent

During certain ability animations, my character gains Push Immunity — I can't be knocked back, pulled, or displaced, but I CAN still be stunned, rooted, or frozen. This lets me commit to a big ability without being pushed out of position, while still being vulnerable to hard CC. A stronger tier grants Full Super Armor — immune to everything.

## Primitive Composition

P-62 (Categorized CC Immunity)

*See `ability-primitives/` for canonical definitions.*

## Inputs

- Caster entity (automatic during ability animations)
- No target (self-applied)

## Observable Behavior

1. Begin casting a heavy ability — gain Push Immunity for the cast duration
2. While Push Immune: knockback (SK-01 Toss), pull (SK-43 Drag), charge (SK-34), vortex (SK-31) — all BLOCKED
3. While Push Immune: stun (SK-24), root (SK-25), silence (SK-26), fear (SK-78), sleep (SK-27) — still APPLY
4. Cast completes — Push Immunity ends
5. Some abilities grant Full Super Armor instead: ALL CC blocked (same as SK-51 Unstoppable)
6. Super Armor tier is visible as a buff icon with the specific immunity level
7. Visual: blue glow for Push Immune, yellow glow for Full Super Armor

## Engine Primitives Required

Partial CC Immunity is now a canonical `self_cc_immunity_during_cast` /
`cc_immunity_categories` reference.

The canonical lowering is:

1. for animation-bound immunity, author `self_cc_immunity_during_cast` on the ability:
   - `push_immune` lowers to a temporary positive status with
     `cc_immunity_categories = [displacement]`
   - `full_super_armor` lowers to a temporary positive status that blocks every canonical CC
     category
2. for nonstandard/custom immunity mixes, author an ordinary positive status directly with the
   desired `cc_immunity_categories`
3. let incoming CC admission check those categories on the target before the CC enters the active
   status registry

This keeps the mechanic entirely inside the canonical CC-immunity surface:

- no bespoke per-type immunity flag table is needed beyond canonical CC categories
- push immunity is already defined as displacement-only immunity
- full super armor is just the full-category version of the same system
- blocked CC components are rejected before admission rather than admitted and then neutralized

## Cross-Boundary Concerns

Partial CC Immunity is enforced entirely on the target's authoritative owner.

1. Cross-boundary CC attempts arrive as ordinary target-owner CC applications.
2. The target owner checks active `cc_immunity_categories` and any temporary cast-time immunity
   status generated by `self_cc_immunity_during_cast`.
3. If the category is blocked, only the CC component is rejected; sibling damage/heal payloads from
   the same ability still resolve normally.
4. The attacker never needs an out-of-band "target is push immune" hint.

## Compiler Requirements

Designer specifies:

- whether the ability grants `none`, `push_immune`, or `full_super_armor` during cast
- any custom positive status that should grant a different CC-category subset

Compiler emits:

- `self_cc_immunity_during_cast` metadata for standard cast-bound tiers
- temporary positive status metadata using canonical `cc_immunity_categories`
- ordinary CC applications whose admission path consults those categories

Compiler validates:

1. cast-bound immunity tiers use only the canonical `none` / `push_immune` / `full_super_armor`
   vocabulary
2. custom immunity sets use canonical CC category names only
3. the mechanic remains CC-only immunity; it does not silently widen into damage immunity or
   targetability denial

## Resolved Interaction Notes

- Push immunity blocks displacement only. It does not block fear/charm forced movement, roots,
  stuns, taunts, or mute unless the authored status includes those categories too.
- `SK-88 Positional Leash` is a movement-constraint status, not a displacement CC category, so push
  immunity does not automatically remove or block it.
- Multiple immunity sources stack by union of blocked categories: if any active status blocks a
  category, that category is rejected on admission.
- Blocked CC applications do not advance DR, because they never admit and therefore never record a
  DR application.
- Execute is not CC, so CC immunity does not stop a valid execute from resolving.
